# FocusFlow —— 个人专注与任务管理工具 PRD

> 文档版本：V1.0  
> 项目阶段：产品需求定义  
> 项目定位：个人专注效率工具 / GitHub 展示项目  
> 目标平台：Web  
> 目标交付：GitHub 开源仓库 + 在线 Demo

---

## 1. 项目背景

番茄钟类工具的核心逻辑并不复杂，但很多简单实现只停留在“25 分钟倒计时 + 开始/暂停/重置”的 Demo 层面，用户很难把一次专注和真实任务关联起来，也无法持续查看自己的专注记录。

FocusFlow 希望解决的不是“有没有一个计时器”，而是：

1. 用户今天具体要做什么；
2. 当前这一轮专注对应哪个任务；
3. 一个任务预计需要多少轮专注；
4. 实际完成了多少轮；
5. 今天、本周到底投入了多少专注时间；
6. 页面切到后台或刷新后，计时是否仍然可信。

因此，FocusFlow 将番茄钟、任务管理、专注 Session 和简单统计整合为一套轻量工作流。

---

## 2. 产品定位

FocusFlow 是一个面向个人使用的本地优先专注效率工具。

用户无需注册账号，打开网页即可创建任务、开始专注、完成休息，并查看当天和最近 7 天的专注数据。

V1.0 的核心定位不是复杂项目管理，而是：

> 用最少的操作完成“任务 → 专注 → 记录 → 反馈”的闭环。

---

## 3. 产品目标

### 3.1 用户目标

用户能够完成以下完整流程：

```text
创建任务
  ↓
设置预计番茄数
  ↓
选择当前任务
  ↓
开始专注
  ↓
暂停 / 恢复 / 重置
  ↓
完成一次 Focus Session
  ↓
进入短休息或长休息
  ↓
任务完成番茄数自动增加
  ↓
查看今日与最近 7 天统计
```

### 3.2 项目目标

V1.0 完成后，应达到“可长期使用的个人工具”标准，而不是一个只能演示的玩具页面。

项目需要做到：

- 核心流程完整；
- 页面刷新后数据不丢失；
- 后台切换后计时不明显漂移；
- 任务与专注记录能够关联；
- 统计数据来源清晰；
- 桌面端和移动端均可正常使用；
- 能够部署为公开在线 Demo；
- GitHub 仓库具备完整 README、文档、测试和开发记录。

---

## 4. 非目标

V1.0 明确不做以下能力：

- 用户注册与登录；
- 云数据库；
- 多设备同步；
- 团队协作；
- 好友系统；
- 评论或社区；
- AI 自动拆解任务；
- 日历同步；
- 邮件提醒；
- 移动端原生 App；
- 服务端推送；
- 复杂项目管理；
- 子任务；
- 标签；
- 优先级；
- 截止日期；
- 多用户权限。

这些能力不属于 V1.0 范围，不因为开发过程中“顺手能做”而加入。

## 5. 目标用户

### 5.1 核心用户

适用于：

- 学生；
- 程序员；
- 自由职业者；
- 内容创作者；
- 需要长时间专注工作的个人用户。

### 5.2 典型需求

用户通常会有以下需求：

- “我今天有几个任务，希望按番茄钟逐个完成。”
- “我想知道这个任务实际用了几个番茄。”
- “我切到 VS Code 后，希望网页里的计时还是准确的。”
- “我不想注册账号，但刷新页面后任务和数据不能丢。”
- “我想知道今天和最近一周到底专注了多久。”

## 6. 核心使用场景

### 场景一：快速开始专注

用户打开 FocusFlow，没有创建任务，直接点击开始。

系统允许用户开启一个未关联任务的 Focus Session。

适合临时专注场景。

---

### 场景二：围绕任务专注

用户创建任务：

```text
完成 FocusFlow README
预计番茄：3
```

然后将该任务设为当前任务并开始专注。

每完成一次 Focus Session：

```text
已完成番茄数 +1
```

最终用户可以看到：

```text
完成 FocusFlow README
3 / 3
```

---

### 场景三：后台继续计时

用户开始 25 分钟专注后切换到 VS Code、浏览文档或其他标签页。

重新回到 FocusFlow 时：

- 剩余时间应根据真实经过时间更新；
- 不因浏览器后台限频而明显漂移；
- 页面标题可显示剩余时间。

---

### 场景四：刷新页面恢复

用户正在专注时误刷新页面。

重新进入后：

- 当前模式仍然存在；
- 当前任务仍然存在；
- 已经过去的时间不会被重置；
- 若计时已经结束，则进入完成处理。

---

### 场景五：查看专注反馈

用户完成一天工作后打开统计区。

可以看到：

- 今日完成番茄数；
- 今日专注分钟数；
- 今日完成任务数；
- 当前连续专注天数；
- 最近 7 天专注分钟趋势。

---

V1.0 分为五个核心模块：

```text
FocusFlow
│
├── Timer
│   └── 专注 / 短休息 / 长休息
│
├── Tasks
│   └── 任务创建、编辑、删除、完成、当前任务
│
├── Sessions

│   └── 今日 / 最近 7 天 / 连续天数

```

# 10. Timer 模块

## 10.1 模式

Timer 包含三种模式：

- Focus；
- Short Break；
- Long Break。

默认时长：

| 模式 | 默认时间 |
|---|---:|
| Focus | 25 分钟 |
| Short Break | 5 分钟 |
| Long Break | 15 分钟 |

默认规则：

> 每完成 4 次 Focus，下一次休息进入 Long Break。

---

## 10.2 Timer 状态

Timer 至少包含四个用户可感知状态：

- Idle：未开始；
- Running：正在运行；
- Paused：暂停；
- Completed：本轮完成。

---

## 10.3 开始

用户在 Idle 状态点击“开始”后：

- Timer 进入 Running；
- 按当前模式开始倒计时；
- 若存在当前任务，则本轮专注与当前任务关联；
- 页面标题开始显示剩余时间。

---

## 10.4 暂停

用户点击“暂停”后：

- 倒计时停止；
- 当前剩余时间保留；
- 页面显示“继续”按钮；
- 暂停期间不继续消耗剩余时间。

---

## 10.5 继续

用户点击“继续”后：

- 从暂停时的剩余时间恢复；
- Timer 返回 Running。

---

## 10.6 重置

用户点击“重置”后：

- 当前模式仍然保持；
- 剩余时间恢复为该模式设定时长；
- 当前未完成 Session 不计入已完成番茄；
- 若当前轮已经运行过，需要二次确认，避免误触。

确认文案：

> 当前专注尚未完成，确定重置吗？

---

## 10.7 跳过

允许用户主动跳过当前阶段。

规则：

- 跳过 Focus：不计为完成番茄；
- 跳过 Break：直接进入下一轮 Focus；
- 跳过操作需要保留当前任务。

---

## 10.8 Focus 完成

当 Focus 倒计时自然结束：

系统需要：

1. 标记本轮 Focus Session 完成；
2. 保存 Session；
3. 若有关联任务，则该任务完成番茄数 +1；
4. 今日番茄数同步增加；
5. 播放提示音；
6. 显示应用内提示；
7. 若浏览器通知已授权，则发送系统通知；
8. 根据当前完成轮数决定进入 Short Break 或 Long Break。

---

## 10.9 Break 完成

Break 自然结束后：

- 不增加任务番茄数；
- 播放提示音；
- 显示提醒；
- 下一模式切换为 Focus；
- 当前任务保持不变。

---

## 10.10 自动开始

设置项包括：

- Auto Start Break；
- Auto Start Focus。

默认：

```text
Auto Start Break = OFF
Auto Start Focus = OFF
```

如果关闭：

完成后仅切换模式，不自动开始。

如果开启：

完成当前阶段后自动启动下一阶段。

---

## 10.11 后台计时要求

Timer 必须满足：

- 浏览器切换到后台后仍以真实时间为准；
- 回到页面后剩余时间应自动校准；
- 不允许仅依赖“每秒执行一次”作为时间事实来源；
- 允许 UI 刷新频率发生变化，但实际剩余时间应保持可信。

验收示例：

```text
开始 5 分钟测试计时
↓
切换标签页 3 分钟
↓
返回 FocusFlow
↓
剩余时间应接近 2 分钟
```

---

## 10.12 页面刷新恢复

Running 状态刷新页面后：

- 不应重新开始完整时长；
- 系统应恢复剩余时间；
- 当前任务不丢失；
- 当前模式不丢失。

Paused 状态刷新后：

- 仍保持 Paused；
- 剩余时间保持暂停时数值。

---

# 11. 任务模块

## 11.1 创建任务

用户点击“添加任务”后输入：

必填：

- 任务名称。

选填：

- 预计番茄数。

默认预计番茄数：

```text
1
```

限制：

- 任务名称不能为空；
- 任务名称最大 80 个字符；
- 预计番茄数最小为 1；
- 预计番茄数最大为 99。

---

## 11.2 任务字段

用户可感知字段包括：

- 标题；
- 预计番茄数；
- 已完成番茄数；
- 状态；
- 创建时间。

内部可以保留完成时间，但不要求在主页面直接展示。

---

## 11.3 当前任务

任意时刻最多只有一个：

> Active Task

用户点击任务的“开始专注”后，该任务成为当前任务。

主 Timer 区域需要显示当前任务名称。

---

## 11.4 切换当前任务

Timer 未运行时：

可以直接切换任务。

Timer 正在运行时：

用户尝试切换任务，需要提示：

> 当前专注正在进行，切换任务后本轮记录将关联到新任务。确定切换吗？

V1.0 允许切换，但必须明确提醒。

---

## 11.5 编辑任务

支持修改：

- 任务名称；
- 预计番茄数。

已经产生的 Session 不受编辑影响。

---

## 11.6 完成任务

用户可以主动标记任务为完成。

完成后：

- 从默认待办区域移出；
- 今日完成任务数增加；
- 历史 Session 保留；
- 如果该任务是当前任务，则清除 Active Task。

---

## 11.7 删除任务

任务可以删除。

如果任务从未产生 Session：

直接删除。

如果任务已经存在 Session：

需要二次确认：

> 该任务已有专注记录。删除任务不会删除历史专注记录，确定继续吗？

历史 Session 必须保留。

---

## 11.8 番茄进度显示

任务列表显示：

```text
已完成 / 预计
```

例如：

```text
完成 README
2 / 3
```

如果实际完成数超过预计数：

```text
4 / 3
```

允许继续记录，不限制用户继续专注。

---

# 12. Session 模块

## 12.1 Session 定义

每一次实际开始的专注阶段都形成一个 Session。

Session 是统计模块的事实来源。

---

## 12.2 Focus Session

Focus Session 至少记录：

- 唯一 ID；
- 关联任务 ID；
- Session 类型；
- 开始时间；
- 结束时间；
- 计划时长；
- 实际时长；
- 是否完成。

未关联任务时：

```text
taskId = null
```

允许存在。

---

## 12.3 完成 Session

仅自然倒计时完成的 Focus Session 计入：

- 已完成番茄；
- 今日 Focus 数；
- 任务完成番茄数；
- 连续专注天数。

---

## 12.4 未完成 Session

以下情况属于未完成：

- 用户重置；
- 用户跳过 Focus；
- 用户主动结束。

V1.0 可以保存未完成 Session，但：

- 不计入番茄完成数；
- 不计入 Streak；
- 不增加任务完成番茄。

统计中的“专注分钟数”默认只统计 completed Focus Session。

---

# 13. Statistics 模块

## 13.1 今日统计

至少展示：

- 今日完成番茄数；
- 今日专注分钟数；
- 今日完成任务数。

---

## 13.2 今日完成番茄数

统计口径：

> 当地自然日内 completed = true 的 Focus Session 数量。

---

## 13.3 今日专注分钟数

统计口径：

> 当地自然日内 completed = true 的 Focus Session 实际专注时长之和。

不直接使用：

```text
番茄数 × 当前设置时长
```

避免用户修改 Focus 时长后产生错误统计。

---

## 13.4 今日完成任务数

统计：

> 当天首次被标记为完成的任务数量。

---

## 13.5 最近 7 天趋势

展示最近连续 7 个自然日。

图表指标：

> Focus Minutes

即每天已完成 Focus Session 的专注分钟数。

无数据日期显示：

```text
0
```

不能直接省略日期。

---

## 13.6 连续专注天数

规则：

当天至少完成 1 个 Focus Session，则当天视为活跃。

连续自然日均有至少 1 个完成的 Focus Session：

```text
Current Streak +1
```

中间出现没有完成 Session 的自然日：

```text
Streak 重置
```

---

# 14. Settings 模块

## 14.1 时间设置

允许配置：

- Focus Duration；
- Short Break Duration；
- Long Break Duration；
- Long Break Interval。

建议范围：

| 设置 | 最小 | 最大 |
|---|---:|---:|
| Focus | 1 min | 120 min |
| Short Break | 1 min | 60 min |
| Long Break | 1 min | 120 min |
| Long Break Interval | 1 | 12 |

---

## 14.2 修改时长时的规则

Timer 处于 Idle：

修改后立即生效。

Timer 处于 Running 或 Paused：

新的设置只影响下一轮。

当前进行中的 Timer 不重新计算。

---

## 14.3 自动开始设置

提供：

- 自动开始休息；
- 自动开始下一轮专注。

默认均关闭。

---

## 14.4 声音设置

支持：

- Sound ON；
- Sound OFF。

默认：

```text
ON
```

关闭后不播放 Focus/Break 完成音效。

---

## 14.5 通知设置

支持：

- Desktop Notification ON；
- Desktop Notification OFF。

首次开启时请求浏览器通知权限。

---

# 15. Notification 需求

## 15.1 应用内通知

无论浏览器通知权限状态如何，都必须支持应用内提示。

例如：

```text
专注完成，休息一下吧。
```

以及：

```text
休息结束，准备开始下一轮专注。
```

---

## 15.2 浏览器通知

只有同时满足以下条件才发送：

- 浏览器支持 Notification API；
- 用户主动开启；
- 权限状态为 granted。

---

## 15.3 权限被拒绝

如果权限为 denied：

- 不重复弹出权限请求；
- 不影响 Timer；
- 不影响音效；
- 不影响应用内提醒；
- 设置中显示“浏览器通知权限已被拒绝”。

---


Break：

```text

```

未运行：

```text

```

# 17. 本地数据持久化

## 17.1 基本要求

以下数据刷新页面后必须保留：

- Tasks；
- Sessions；
- Settings；
- Timer 当前状态；
- Active Task。

---

## 17.2 数据版本

本地数据必须存在版本号。

例如：

```text
version: 1
```

目的是为后续字段调整或迁移保留升级能力。

---

## 17.3 数据损坏

如果本地数据无法正常读取：

- 应用不得白屏；
- 自动回退至安全默认状态；
- 显示一次用户可理解的提示。

例如：

> 本地数据读取失败，已恢复默认配置。

---

## 17.4 清除数据

Settings 中提供：

> Reset All Data

执行前必须二次确认。

确认内容：

> 此操作会清除所有任务、专注记录和设置，且无法恢复。确定继续吗？

---

# 18. 空状态

## 18.1 无任务

任务区域显示：

> 还没有任务，创建一个任务开始今天的专注吧。

同时提供：

> 添加任务

按钮。

---

## 18.2 无统计数据

最近 7 天全部无专注记录时：

仍显示图表框架和 0 数据。

并提示：

> 完成第一轮专注后，这里会开始记录你的专注趋势。

---

# 19. 用户体验要求

## 19.1 核心操作步数

从进入首页到开始无任务 Focus：

最多：

```text
1 次点击
```

已有任务情况下：

```text
选择任务
→ 开始
```

最多 2 次核心操作。

---

## 19.2 视觉优先级

页面视觉优先级：


# 22. 异常场景

## 22.1 音频播放失败

处理：

- 忽略音频错误；
- Timer 正常完成；
- Session 正常保存；
- 通知正常显示。

---

## 22.2 Notification API 不支持

处理：

- 隐藏或禁用浏览器通知能力；
- 使用 Toast 和 Audio；
- 不影响其他功能。

---

## 22.3 页面长时间关闭

用户在 Running 状态关闭页面，结束时间已经过去后再次打开：

系统需要识别当前 Timer 已经过期。

不得恢复一个负数倒计时。

V1.0 处理原则：

- 当前 Timer 进入完成状态；
- 不重复生成多个完成记录；
- 同一次 Timer 最多产生一个完成 Session。

---

## 22.4 快速重复点击

Start、Pause、Complete 等关键操作需要避免重复触发。

例如：

用户连续双击 Start：

不得创建两个 Session。

---

# 23. 数据一致性规则

V1.0 遵守以下规则：

1. 一个运行中的 Timer 同一时刻只能对应一个 Session；
2. 一个 Focus Session 最多完成一次；
3. 一个完成 Session 对任务完成番茄数最多增加 1；
4. 删除 Task 不删除 Session；
5. 修改 Task 名称不修改已有 Session；
6. 修改设置不修改已经完成的 Session；
7. 统计数据以 Session 为事实来源；
8. UI 显示的数据不得与 Session 历史相互矛盾。

# 26. V1.0 验收场景

## AC-01 正常完成 Focus

前置：

- Focus = 25 min；
- 当前任务 A；


预期：

- Task A 完成数变为 1；
- 今日完成番茄 +1；
- 今日专注分钟增加；
- 显示完成提醒；

## AC-02 暂停与恢复

操作：

```text
Start

→ 等待一段时间
→ Resume
```

预期：

```text
→ Refresh
```

预期：

# 31. V1.0 最终范围确认

FocusFlow V1.0 最终只围绕以下主线开发：

```text
Task
 ↓
Active Task
 ↓
Pomodoro Timer
 ↓
Focus Session
 ↓
Local Persistence
 ↓
Statistics
```

所有新增需求都需要判断：

> 是否直接增强这条核心链路？

如果不能，则默认不进入 V1.0。

项目第一阶段的目标不是“功能最多”，而是：

> 核心流程完整、数据逻辑清楚、使用体验稳定、GitHub 展示专业。

## V1.1 追加需求：中英文界面

2026-10-28 确认：应用默认使用中文，右上角提供中文 / English 选择，切换立即生效并记住选择。

- 翻译覆盖计时、任务、统计、设置、弹窗、页面提示、通知和无障碍标签。
- 用户输入的任务名称保持原文。
- 切换语言保留运行或暂停状态、Session ID、截止时间、任务进度与未提交输入。
- 旧版本未保存语言的用户默认使用中文，原有任务和记录保持不变。
- 语言切换入口支持键盘操作，并在桌面、375px / 390px 手机和横屏布局中可用。

设计与验收见 [中英文界面更新](13-LANGUAGE.md)。

## V1.2 追加需求：数据备份与恢复

设置弹窗增加“备份与恢复”，导出全部任务、Session、计时状态与设置为 JSON 文件。导入时先校验并展示备份时间、任务数和记录数，用户确认后替换当前数据；取消或任何校验、存储失败均保留原数据。

- 文件大小上限 5 MB，支持旧数据 schema 迁移；不支持的未来版本拒绝导入。
- 运行中的计时按备份时刻保存剩余时间，导入后以暂停状态恢复，保持 Session ID，不补算备份后的时间。
- 通知权限不随文件转移，当前浏览器未授权时关闭导入的通知开关。
- 中英文、键盘、浅色 / 深色与手机尺寸均可用，不新增后端、账号或云存储。

详见 [备份设计与验收](14-BACKUP.md)。
